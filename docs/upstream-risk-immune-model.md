# 上游风控免疫系统模型（跨界连接 · 免疫学 → 网关适配）

> 从三种"受限上游"（GLM 匿名 40012 / DeepSeek 登录墙 / 任意外部风控）的实战中提炼。
> 免疫学类比让判断更结构化：先分类风控类型，再选对应策略，避免死磕错误层。

## 核心映射

| 免疫学概念 | 上游风控现实 | 对应策略 |
|---|---|---|
| 先天免疫（通用规则，对所有异常请求生效） | IP 级风控 40012（换 token/换会话照样拒） | **换环境**（新 IP/新设备指纹），参数层调优无效 |
| 适应性免疫（学习特定行为模式） | 请求特征指纹（TLS 栈/JS 上下文/UA 组合） | **借用真实客户端通道**（浏览器 UI/官方 SDK），别复刻请求 |
| 免疫记忆（同一抗原二次应答更快更强） | 同一 IP/token 反复触发后惩罚加重、恢复窗口变长 | 冷却期策略：触发后**主动放弃**该 token/IP，别密集重试（重试=喂养记忆） |
| 自身细胞（不被免疫系统攻击） | 真实浏览器页面正常请求 | 这就是通道的"合法身份"——UI 驱动天然通过 |
| 免疫耐受（对长期存在的抗原不再应答） | 冷却期 30 分钟后 token 可能恢复 | 会话池设计：take→用→冷却→30min 自动恢复（已验证） |

## 判断三步法（当一个"不明风控"出现时）

1. **分类**：换 token/换会话/换端口后是否仍然 4xx？
   - 仍拒 → **先天免疫/IP 级** → 换环境（新 IP），参数层别再试
   - 换后放行 → 适应性/额度级 → 冷却+轮换即可
2. **对照**：真实浏览器/官方客户端同款请求是否可用？
   - 可用 → 我们在被"指纹识别"→ 放弃复刻，转 UI 驱动（三连同 4xx + 页面可用 = 立刻转）
   - 不可用 → 上游整体故障/策略升级 → 等恢复或换上游
3. **计量**：记录最后一次探测时间+结果。间隔 < 30 分钟不重测（密集触发=喂养免疫记忆，可能延长封锁）

## 反模式（都会延长封锁或浪费轮次）

- ❌ 同一 token 连测 3 次以上（边际产出递减 + 惩罚加重）
- ❌ 复刻请求参数层"全对齐"仍被拒，还继续调参（三连信号已足够）
- ❌ 不做间隔记录，每轮心跳都去撞墙（详见 TODO 外部风控停止准则）

## 适用范围

- glm2api 匿名会话池（token 冷却/轮换）
- deepseek2api 账户轮换
- api-proxy key RPM 感知轮换（8.25s 冷却 + 429 双倍惩罚 = 免疫记忆的工程实现）
